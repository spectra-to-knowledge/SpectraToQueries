## 1. Specification summary

- Input: MS2 spectra with a `SKELETON` class label. Positive class = one
  skeleton; negatives = all other MS2 spectra with a non-empty label.
- Match rule (fragment m/z `f`): a peak `x` with
  `|x - f| <= dalton + f * ppm / 1e6` (Da). Neutral loss `n` (Da), precursor m/z
  `p`: fragment target `p - n`, required `> 0`, same rule on `p - n`.
- Peak filter: relative intensity `100 * I / max(I) >= intensity_min`.
- Score: MCC = (TP·TN − FP·FN) / sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN)), 0 when the
  denominator is 0. Selected query per skeleton: max MCC rounded to `decimals`,
  then fewest ions, unrounded MCC, precision, fragment count.
- Glossary: *m/z* (fragment, Th); *neutral loss* (Da, `p - fragment m/z`);
  *feature* (one `_frag` or `_nl` column); *skeleton* (class label);
  *conjunction* (`&` of ion tokens); *hit* (ion matched in a spectrum).

## 6. Open questions

- **OQ1 (MS2NL tolerance). Resolved (F22).** Maintainer chose option (a): the
  pipeline evaluates neutral losses with the emitted MassQL window.
- **OQ2 (`INTENSITYPERCENT` boundary).** MassQL keeps `> threshold`, the
  pipeline `>= intensity_min`. Differs only at exact equality. Recommendation:
  keep `>=` and document (current).
- **OQ3 (`" ; "` separator).** Not part of the MassQL grammar; GNPS batch
  workflows use `|||`. Only reachable from user-supplied disjunctive input.
  Recommendation: return one element per clause (list) or switch to `|||` after
  confirming the target runner.
